# apps/

可独立启动、可独立部署的应用层。每个子目录是一个工作区包（`@nomitr/<目录名>`），必须有自己完整的启动入口与构建产物。

## 成员

| 目录 | 包名 | 职责 | 部署形态 |
| --- | --- | --- | --- |
| `web/` | `@nomitr/web` | 博客前台，面向读者的公开站点 | 静态站点或服务端渲染应用 |
| `admin/` | `@nomitr/admin` | 内容管理后台，面向作者的写作与运营界面 | 普通前端应用 |
| `api/` | `@nomitr/api` | 后端服务，提供文章、评论、认证等接口 | 常驻服务进程 |

## 规则

1. **应用之间不互相引用**。两个 app 都要用的代码，下沉到 `packages/`。
2. **应用可以引用任何 `packages/*`**，但只走包名（例如 `@nomitr/ui`），不写相对路径跨目录 import。
3. **应用自己独占的资源留在本地**：页面、路由、仅本站使用的组件放各自的 `src/`，不要为了"复用可能性"提前上提。
4. **一个应用一个部署单元**。`deploy/` 下的配置按应用名分组，不混用。
5. 新增应用时，同步更新本文件、根 `README.md` 的目录树，以及 `docs/architecture.md` 的依赖图。
