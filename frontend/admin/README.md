# @nomitr/admin（文章管理后台）

只有你自己使用的写操作界面。和游客站是**两个独立应用**：不同入口、不同构建、可以单独部署到独立域名（例如 `admin.example.com`），也可以只在内网访问。

## 职责

- 文章的增删改查：新建、编辑、预览、发布、下架、草稿管理。
- 标签与归档维护。
- 所有写操作走 `backend` 的写接口，前端不直连数据库、不写文件。
- 登录态管理：令牌存储、过期处理、401 统一跳登录。

**不做什么**：不渲染读者页面，不与游客站共享路由。

## 建议的 src 结构

```text
src/
├─ pages/         # 登录、文章列表、编辑器、标签管理、设置
├─ components/    # 后台专用：数据表格、表单控件、编辑器外壳
├─ features/      # 按业务域聚合：articles/、tags/、auth/
├─ services/      # 接口封装 + 鉴权拦截器（统一出口）
├─ stores/        # 登录态、编辑器草稿等客户端状态
└─ styles/        # 后台主题
```

## 依赖边界

- 可以引用：`@nomitr/ui`、`@nomitr/shared`、`@nomitr/config`。
- 接口类型来自 `@nomitr/shared` 的 `types/api/`，与游客站共用同一份定义。
- 不可以引用：`@nomitr/web` 的任何文件，以及 `backend/` 的源码。
- 表单控件、编辑器外壳等若游客站也会用到（如评论框），提升到 `@nomitr/ui`。

## 安全约定

- 后台的鉴权以服务端为准，前端隐藏入口不算防护。
- 令牌不放 `localStorage` 以外的可被脚本随意读取的位置之前先想清楚 XSS 面；至少做到统一封装、集中清理。
- 生产环境走 HTTPS，后台域名与游客站分离部署时注意 CORS 白名单只放指定域名。
