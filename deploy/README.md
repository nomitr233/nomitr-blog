# deploy/

部署编排，按平台分目录。原则：**一个应用一个部署单元**，配置里不出现跨应用的隐式依赖。

## 目录

| 目录 | 内容 |
| --- | --- |
| `docker/` | 各应用的镜像构建文件与本地编排（compose），一应用一 `Dockerfile` |
| `nginx/` | 反向代理与静态站点配置，负责域名、证书、缓存头、动静分离 |

## 约定

- 配置里的应用名与 `apps/` 下的目录名一致，例如 `deploy/docker/web.Dockerfile`、`deploy/nginx/web.conf`。
- 密钥、证书、数据库密码不入库，通过环境变量或部署平台的 secret 注入；仓库里只放 `.env.example`。
- 每个环境（dev / staging / prod）的差异用覆盖文件表达，不要复制整份配置。
- 新增应用时，在这里补对应的构建文件与代理配置，并更新本表。
